# Interface translations

Catalogs: `app/i18n/<code>.txt`, one `English key<TAB>translation` per line, compiled in at configure time.
`tests/app/test_i18n.cpp` fails on stale keys (not used by any `tr()`/`trw()`/`N_()` in `app/`) and on changed printf conversions.

## Finding what is untranslated

```
python3 tools/i18n_missing.py              # count per language
python3 tools/i18n_missing.py de           # keys of one language
python3 tools/i18n_missing.py --common     # union over all languages
build/test_i18n --dump > used.txt; python3 tools/i18n_missing.py --used used.txt   # also keys missing from catalogs
```

A key is untranslated when its catalog text equals the English key. Texts that stay the same everywhere
(units, acronyms, standards) are listed in `tools/i18n_keep_english.txt` and skipped. Remaining hits can be
real untranslated texts or words that are spelled the same in that language (Radio, Menu, Auto): review them.

## After merging new branches (procedure)

1. Build and run `test_i18n`; its warning lists the used texts missing from catalogs.
2. Add each new key to every catalog (English text as the translation if you do not translate), keep the sections sorted as the file is.
3. Run `tools/i18n_missing.py --common`, translate per language, keep placeholders (`%s`, `%d`, `\n`) and acronyms.
   A key with a `##id` suffix keeps the suffix in the translation.
4. List newly machine-translated keys in `app/i18n/unreviewed/<code>.txt` (one key per line); remove a line when a native speaker checked it.
5. Re-run `test_i18n`.

Machine-translated, unreviewed entries are marked in the header of each catalog and listed in `app/i18n/unreviewed/`.
